# Security and privacy

## Local access

The CDP endpoint grants control over the signed-in Teams session. Bind it to
`127.0.0.1`, use trusted local tools, and close the debug-enabled app when that
access is no longer needed. The CLI does not provide an authorization layer for
other processes that can connect to CDP.

Reads use local cache/DOM data or passively observe responses generated by Teams.
Writes use the UI. The project does not make independent Teams service requests
using credentials taken from the page. This describes implementation behavior;
it does not establish permission for a particular account or organization.

## Data handled by the CLI

Command output can contain private conversation content, names, account IDs,
calendar details and attachment data. Captured content is marked as untrusted
input for agents. These labels do not make it safe to publish.

Traces omit message bodies, typed values, scripts, clipboard contents and raw
protocol payloads. They still contain operation metadata, identifiers and timing.
Treat them as private unless individually reviewed. Traces are append-only and
are not automatically deleted or rotated. Inspect their location with the trace
reference returned by a command.

## Public examples and reports

Use synthetic fixtures and fictional names/identifiers. Do not commit:

- Live chat exports, attachments, screenshots or calendar data.
- Browser profiles, session storage, cookies, credentials or signed download URLs.
- Raw network captures, private traces or downloaded Teams client bundles.
- Local agent configuration or environment files containing credentials.

`.scratch/`, local exports, trace directories and common credential files are
ignored by Git. Ignore rules do not remove previously committed files and do not
protect arbitrary archives of the working directory. Review the staged diff and
history before publication; use a tracked-file export rather than zipping the
whole checkout.

For a security report, share a minimal synthetic reproduction. Do not post live
credentials or private account data in a public issue. This repository does not
currently publish a dedicated private reporting address; establish a private
channel with the maintainer before sharing sensitive details.
