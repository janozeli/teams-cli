# Contributing

Start with the [README](README.md), [architecture](docs/ARCHITECTURE.md) and
[backlog](BACKLOG.md). Coding agents should also read [AGENTS.md](AGENTS.md).

## Development checks

```sh
npm ci
npx playwright install chromium
npm run typecheck
npm test
npm run build
npm run check:skill
```

If command help changes, run `npm run build:skill` and include the generated skill.
Tests run against synthetic data and isolated browser profiles. Keep fixtures
small and focused on behavior, including refusal paths and uncertain outcomes.

## Integration constraints

- Read local cache/DOM data or passively observe traffic generated by Teams.
  Do not implement independent service requests using page credentials.
- Perform writes through the UI, bind controls to the intended target, and verify
  the result. Arm observation before any action whose response is needed.
- Preserve the distinction between not dispatched, dispatched but unverified, and
  confirmed. Do not retry a write blindly or resume invalidated work.
- Keep YAML and JSON semantically equivalent, including errors and trace references.
- Preserve third-party notices and the unmodified vendored hook snapshot.

Changes to `src/cdp.ts` or `src/page/scripts.ts` also require live `chats` and
`read me` checks. Use only the self chat for message tests unless a different
recipient has been explicitly authorized. Coordinate manual UI tests with whoever
is using the Teams window.

## Reports and pull requests

Describe the problem, resulting behavior and relevant checks. State whether
validation used fixtures or a live Teams session. Include remaining limitations.
Use fictional names, account IDs, message IDs and content in public examples.
Do not attach raw Teams exports, traces, screenshots, credentials or client bundles;
see [security and privacy](SECURITY.md).
